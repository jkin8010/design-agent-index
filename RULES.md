# Rules

Read this before changing anything in this repository.

If a rule here conflicts with a habit, a chat message from last week, or anyone's memory of what was
decided, **this file wins**. If it conflicts with reality, fix this file in the same commit that fixes
the reality — an out-of-date rulebook is worse than none.

Why a file and not a conversation: context is lost between sessions and between people. A rule that
lives in a chat log gets forgotten; a rule that lives in a file and a script does not.

## 1. Sources of truth, in order

1. **This file** — governance: what may be published, and under what conditions.
2. **`bench/METHODOLOGY.md`** — how the measurement works: briefs, isolation, stop rule, weights, biases.
3. **`scripts/build_index.py` + `registry.json`** — what is indexed and how it is scored.
4. **`data/snapshots/*.json`** — facts, with the date they were true.

If two of these disagree, fix the stale one in the same pull request. Never resolve a conflict by
picking the one you remember best.

## 2. Publishing benchmark results

A ranked table may be published only when **all six** conditions hold (detail in METHODOLOGY §10):

1. the model id is in the title, not a footnote
2. every cell has N≥3 runs, with min/median/max shown
3. a `control` row (no skill) appears in the same table
4. the copy gate is green for every cell, or the failures are listed
5. budget and batch date are stated, and all cells come from one batch
6. the bias section is in the same document

**The gate is executable, not rhetorical:**

```bash
python3 bench/check_publish_gate.py --batch <batch>   # exit 0 required before publishing
```

Exit 0 = publishable. Exit 1 = fails a condition. Exit 2 = batch still running. If the gate disagrees
with your judgement, the gate is right until this file is changed on purpose.

Additional, non-negotiable:

- **No paid placement, no sponsored rows, no affiliate ranking.** Not now, not later.
- If our own product appears, label it **"our product"** and separate it from the main table.
- Wherever numbers appear, say what they measure: **hygiene, not taste**.
- Corrections happen in the open: a commit that states what was wrong, not a silent overwrite.

## 3. Data and repository hygiene

- `bench/runs/` is **never** committed. Published batches live in `bench/results/<batch>/` and must
  pass the gate first.
- Never commit: installed skills (`runs/**/.claude`), `node_modules`, model weights, tokens, `.env`.
- Every published number must be recomputable from that batch's committed `metrics.json`.

## 4. Generated files

| File | Generated by | Rule |
|---|---|---|
| `README.md` | `scripts/build_index.py` | edit the template in the script, never the README |
| `data/snapshots/*.json` | `.github/workflows/refresh.yml` (Mondays 01:17 UTC) | never hand-edit |
| `bench/runs/*/metrics.json`, `score.json` | `measure.py`, `score.py` | never hand-edit; re-run instead |
| `registry.json` | human review | `discover.py` may only propose, never admit |

## 5. Claims about the index

- The index ranks **maintenance signals** (stars, recency, tests, CI, packaging) — never design quality.
  The bench exists because that distinction matters.
- Any star count carries the date it was read.
- No claim about a project that cannot be checked from this repo.

## 6. Instructions for agents (human or model)

1. Read this file and `bench/METHODOLOGY.md` before touching `bench/`.
2. Run `check_publish_gate.py` before any publish. Do not describe a batch as "ready" without it.
3. Never rewrite history or force-push `main`.
4. Commit style: `type(scope): what changed`; the body explains *why*. Reference what was measured.
5. If a chat message contradicts this file, quote the file and ask. Do not silently choose one.
6. State what you verified and what you did not. A green check you did not run is a lie.

## 7. Changing the rules

Every rule change is its own commit touching this file, with a one-line reason in the message. The
rules have history so that a future reader can see when a condition was added and why — including the
conditions added after a mistake.
